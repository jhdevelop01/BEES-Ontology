### 1.4 개발 원칙 문서 생성

사용자 요청: "TTL-First 원칙을 문서화하여 매 세션 참조할 수 있게"

**생성 파일:** `_docs/08_개발_원칙.md`

주요 원칙 7가지:
1. **TTL-First 원칙** — TTL이 Single Source of Truth, Neo4j는 파생 저장소
2. **변경 워크플로우** — TTL 수정 → rdflib 검증 → SHACL 검증 → 문서 업데이트 → Neo4j 동기화
3. **Neo4j 직접 수정 금지** — TTL에 없으면 Neo4j에도 없어야 함
4. **Brick Schema 준수** — 관계 대칭(hasPart↔isPartOf, feeds↔isFedBy), 필수 속성
5. **변경 관리** — 수정 후 필수 체크리스트 10항목
6. **데이터 대통합 원칙** — 다건물 통합, 네임스페이스 마이그레이션
7. **LLM 서비스 경계** — 온톨로지=사실+구조, LLM=해석+표현

## 4. 사용자와 합의된 아키텍처

```
Brick Schema TTL (Single Source of Truth)
        ↓
    rdflib 파싱 검증 + SHACL 검증
        ↓
    Neo4j GraphDB (n10s 플러그인으로 임포트)
        ↓
    LLM → Cypher 쿼리 생성
        ↓
    자연어 응답 반환
```

**핵심 원칙:**
- TTL이 유일한 원본, Neo4j는 파생 런타임 엔진
- 모든 변경은 TTL 먼저 → 검증 → Neo4j 동기화
- 상세 원칙: `_docs/08_개발_원칙.md` 참조
