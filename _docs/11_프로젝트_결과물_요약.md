## 1. 프로젝트 개요

삼성물산 GEC(Green Energy Center) **B동**에 대한 **Brick Schema 기반 건물 온톨로지**를 구축하고,
이를 기반으로 **디지털 트윈 IoT 시뮬레이션 플랫폼**을 개발한 프로젝트.

| 구분 | 내용 |
|------|------|
| 대상 건물 | 삼성물산 GEC B동 (서울 강동구, 2011년 준공, B4~15F) |
| 온톨로지 | Brick Schema 1.3+ 기반, **11,527 트리플, 1,597 인스턴스** (v2.2.2) |
| 플랫폼 | 4개 서버 + 4개 인프라 = Docker 9서비스 + Neo4j |
| 프론트엔드 | **20개 페이지**, 한/영 다국어 (next-intl), 대시보드 D&D 위젯 |
| 실시간 | **WebSocket + SSE 병행**, Browser Push 알림, Email/Slack 알림 |
| 시뮬레이션 | 284개 장비, 691개 센서 포인트 (1초 주기), 시나리오 7종, 고장 주입 6종, 열역학 모델링 |
| 보고서 | JSON / CSV / Excel(openpyxl) / PDF(fpdf2) 4포맷 |

### 4.5 데이터 파이프라인

#### 실시간 데이터 흐름
```
Server C (에뮬레이터)
  ↓ MQTT 발행 (5초 간격)
  ↓ bees/points/{point_id}  →  payload: {value, ts, unit, quality}
  ↓ bees/devices/{id}/state →  payload: {is_active, mode, ts}
  │
Mosquitto MQTT Broker (:1885)
  ├── → Server A Backend (구독)
  │       ├── _point_cache / _device_cache 딕셔너리 캐시
  │       ├── SSE event_generator() → 프론트엔드 실시간 push
  │       └── WebSocket broadcast → _ws_clients (양방향 실시간)
  │
  └── → Server D (구독)
          ├── mqtt_worker.py: 배치 버퍼링
          └── InfluxDB 배치 쓰기 (measurement: sensor_data)

프론트엔드 실시간 수신 (2채널 병행):
  ├── 1순위: WebSocket (/api/stream/ws) — 양방향, 자동 재연결
  └── 2순위: SSE (/api/stream/points) — WebSocket 실패 시 폴백

  → Browser Notification API: 알람 수신 시 Push 알림 표시
```

#### 제어 명령 흐름
```
프론트엔드 (ON/OFF 버튼 클릭)
  ↓ POST /api/control {deviceId, command}
Server A Backend
  ↓ httpx 프록시
Server B (BAS Adapter)
  ├── 디바이스 레지스트리 유효성 검증
  ├── 감사 로그 저장 (PostgreSQL / 인메모리 폴백)
  ↓ httpx 프록시
Server C (에뮬레이터)
  ├── 장비 상태 변경 (ON→OFF, OFF→ON)
  ├── 센서값 물리적 보정 (예: AHU OFF → 급기온도 24°C 수렴)
  ↓ MQTT 발행
Mosquitto → Server A (SSE) → 프론트엔드 실시간 반영
```

#### 시계열 조회 (3단계 폴백)
```
프론트엔드 요청: GET /api/history/{point_id}?start=-1h
  │
  ├── 1순위: InfluxDB 직접 조회 (influxdb_service.py)
  │          Flux 쿼리 + aggregateWindow → source: "influxdb_direct"
  │
  ├── 2순위: Server D 프록시 (Server D → InfluxDB)
  │          httpx GET → source: "server_d_proxy"
  │
  └── 3순위: MQTT 캐시 최신값 (mqtt_service.py)
             메모리 캐시 → source: "mqtt_cache"
```

## 5. 핵심 기술 의사결정

| 결정 사항 | 선택 | 이유 |
|-----------|------|------|
| SSE 방식 | polling (`_event_counter` + `threading.Lock`) | Python 3.12에서 `asyncio.Event` 크로스스레드 불가 |
| Neo4j 배포 | docker-compose 외부 컨테이너 | 기존 데이터 보존, n10s 플러그인 설정 유지 |
| 온톨로지 원칙 | TTL-First (TTL이 Single Source of Truth) | Neo4j는 파생 런타임 엔진, TTL 없이 Neo4j 변경 금지 |
| n10s 필터 | `n.uri STARTS WITH 'https://example.org/gec-b#'` | n10s 내부 노드(_GraphConfig 등) 제외 |
| 프론트엔드 환경변수 | `NEXT_PUBLIC_*` 빌드 시 bake | Next.js standalone 모드, 런타임 변경 불가 |
| 그래프 시각화 | Cytoscape.js (dynamic import) | SSR 회피 + 대규모 노드 렌더링 성능 |
| InfluxDB 조회 | 3단계 폴백 | InfluxDB 직접 → Server D 프록시 → MQTT 캐시 |
| LLM 모델 | GPT-4o Function Calling | Cypher 생성 정확도 + 도구 호출 안정성 |
| 다국어 (i18n) | next-intl "no-prefix" 모드 | URL 변경 없이 cookie 기반 locale 전환, 기본 ko |
| 대시보드 위젯 | react-grid-layout ResponsiveGridLayout | 드래그&드롭 + localStorage 레이아웃 저장 |
| 실시간 채널 | WebSocket + SSE 병행 | WS 우선 → 실패 시 SSE 폴백, 점진적 전환 |
| 환경 설정 | pydantic-settings BaseSettings (4개 서버 전체) | `.env` 자동 로딩, 타입 검증, dev/prod 분리 기반 |
| PDF 한글 | fpdf2 + NanumGothic TTF 임베딩 | 서버사이드 PDF 생성, 한글 폰트 지원 |
| 보고서 Excel | openpyxl | 서버사이드 Excel 생성, 서식/차트 지원 |
