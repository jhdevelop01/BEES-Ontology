## 1. 토폴로지가 보여주는 것: "에너지와 유체의 흐름"

화면에서 **화살표로 연결된 모든 선은 `feeds` 관계**, 즉 **"A가 B에게 에너지/유체를 공급한다"**는 의미입니다.

GEC B동에서 흐르는 4가지 주요 흐름:

### 1.1 냉수(CHW) 흐름 — 파란색 라인

```
Chiller_1~4  →  CHW_Pump_1~4  →  CC_Distribution_Header_5F~15F  →  CC_Panel_5F~15F
  (냉동기)       (냉수 펌프)        (층별 분배 헤더)                   (천장 복사 패널)
                                                                         ↓
                                                                    각 층 Zone
```

**의미**: 냉동기가 7°C 냉수를 만들고 → 펌프가 압송하고 → 층별 헤더가 분배하고 → 천장 패널이 실내를 냉방

### 1.2 온수(HW) 흐름 — 빨간색 라인

```
Boiler_1~3  →  HW_Pump_1~3  →  RH_Distribution_Header_5F~15F  →  RH_Panel_5F~15F
  (보일러)       (온수 펌프)       (층별 분배 헤더)                    (복사 난방 패널)
```

**의미**: 보일러가 온수를 만들고 → 펌프 → 헤더 → 패널로 각 층 난방

### 1.3 공조(AIR) 흐름 — 초록색 라인

```
AHU_UFAD_1~11  →  Floor_Diffuser_5F~15F  →  각 층 Zone
  (공조기)            (바닥 취출구)
```

**의미**: 공조기가 공기를 조화하고 → 바닥 취출구로 공기를 공급 → Zone에 도달

### 1.4 냉각수(CW) 흐름 — 보라색 라인

```
Cooling_Tower_1~4  →  CW_Pump_1~4  →  Chiller_1~4
  (냉각탑)              (냉각수 펌프)     (냉동기로 돌아감)
```

**의미**: 냉각탑이 냉동기의 열을 외기로 방출 (냉동기 보조 순환)

## 2. 화면 레이아웃 읽는 법

### 2.1 레벨 열 (왼쪽 → 오른쪽 = 에너지 상류 → 하류)

| 열 | 이름 | 예시 장비 | 역할 |
|:--:|------|----------|------|
| L0 | **소스 (Source)** | Chiller, Boiler, Cooling Tower | 에너지를 **생산** |
| L1 | **1차 (Primary)** | CHW_Pump, HW_Pump, CW_Pump | 에너지를 **이송** |
| L2 | **분배 (Distribution)** | CC_Distribution_Header, RH_Distribution_Header | 층별로 **분배** |
| L3 | **말단 (Terminal)** | CC_Panel, AHU, FCU, RH_Panel | 실내에 **전달** |
| L4 | **공급 (Delivery)** | Floor_Diffuser, VAV | 최종 **토출** |
| Zone | **공간** | B_5F_Interior, Lounge_Zone_2F | 최종 **서비스 대상** |
| L999 | **독립 (Isolated)** | feeds 관계 없는 장비 | 연결 미설정 |

**핵심**: 왼쪽 장비일수록 고장 시 영향 범위가 넓고, 오른쪽 장비일수록 국소적입니다.

### 2.2 장비 카드 구성 요소

```
┌─────────────────────────────────────────┐
│ ▌ CHW_Pump_1              [NORMAL]   🔴 │  ← 알람 배지 (있을 때만)
│ ▌ 냉수 펌프 1                            │  ← 표시 이름
│ ▌ Chilled_Water_Pump                     │  ← Brick 타입
│ ▌ ████████████░░░░░  82%    S:5         │  ← 가동률 + 센서 수
└─────────────────────────────────────────┘
  ← 좌측 컬러바 = 시스템 색상 (파랑=CHW, 빨강=HW, 보라=CW, 초록=AIR, 노랑=ELEC)
```

- **가동률 바**: 초록(>70%) / 노랑(30~70%) / 빨강(<30%)
- **상태 배지**: `NORMAL` / `WARNING` / `STOP`
- **알람 배지** (우상단): 실시간 알람 발생 시 빨강(critical) / 주황(warning) / 파랑(info)

### 2.3 화살표(엣지) 종류

| 유형 | 굵기 | 특징 | 의미 |
|------|:---:|------|------|
| **Inter-system** (시스템 간) | 굵음 (3px) | 라벨 있음 (냉수/온수/냉각수/전력/공기) | 다른 시스템으로 에너지 전달 |
| **Intra-system** (시스템 내) | 보통 (2px) | 라벨 없음 | 같은 시스템 내 흐름 |
| **Zone** (구역) | 얇음 (1.5px) | 점선 | 장비 → 서비스 공간 |

## 3. 얻을 수 있는 인사이트 3가지

### 인사이트 1: 장애 파급 분석 — "이 장비가 고장나면 어디까지 영향?"

1. 빨간색 **"장애 파급 분석"** 버튼을 클릭하여 Impact 모드를 켭니다
2. 분석하고 싶은 장비 카드를 클릭합니다
3. Neo4j가 `feeds` 경로를 최대 5단계까지 추적합니다

**하이라이트 색상 의미:**

| 색상 | 상태 | 의미 |
|------|------|------|
| 빨강 (깜빡임) | fault-source | 장애 원인 장비 |
| 주황 | direct | 직접 영향 (1단계, 바로 연결) |
| 노랑 | indirect | 간접 영향 (2~3단계) |
| 연노랑 | extended | 확장 영향 (4~5단계) |
| 보라 | zone-affected | 영향받는 공간(Zone) |
| 흐림 | dimmed | 영향 없는 장비 |

**실제 데이터 예시 — Chiller_1 클릭 시:**

| 분류 | 수량 | 대표 장비 |
|------|:---:|----------|
| 직접 영향 | 35대 | CHW_Pump, CC_Panel 20개, AHU 10개, DOAS 3개, Cooling Tower |
| 간접 영향 | 81대 | 각 AHU에 연결된 바닥 취출구, FCU 등 |
| 확장 영향 | 2대 | 5단계 말단 장비 |
| 영향 Zone | 50개 | B동 거의 전체 층 |

→ **Chiller_1이 B동에서 가장 크리티컬한 단일 장비**라는 것을 시각적으로 즉시 파악 가능

### 인사이트 2: 시스템 간 의존성 — "시스템이 어떻게 연결되어 있는가?"

굵은 화살표 라인(inter-system edge)에 라벨이 붙어있습니다:

- `냉수` 라벨 — CHW 시스템 → AIR 시스템 (냉동기가 만든 냉수로 공조기가 냉방)
- `냉각수` 라벨 — CW 시스템 → CHW 시스템 (냉각탑이 냉동기를 보조)
- `온수` 라벨 — HW 시스템 → 난방 패널

→ **시스템이 독립이 아니라 서로 의존한다**는 것을 보여줍니다.
예: 냉각탑(CW) 고장 → 냉동기(CHW) 과열 → 냉방 전체 중단

### 인사이트 3: 운영 상태 전체 조감도

각 카드에 실시간(SSE)으로 표시되는 정보:

- **가동률 바**: 장비의 현재 운전 상태를 0~100%로 표시
- **상태 배지**: NORMAL(정상) / WARNING(주의) / STOP(정지)
- **알람 배지**: 실시간 알람 발생 장비에 빨간(critical) / 주황(warning) / 파란(info) 점

→ 전체 빌딩의 HVAC 건강 상태를 **한 화면**에서 파악 가능

## 4. 컨트롤 패널 기능

### 4.1 시스템 필터

상단 버튼으로 특정 시스템만 표시/숨김 가능:
- **All**: 전체 시스템 토글
- **냉수(CHW)** / **온수(HW)** / **냉각수(CW)** / **전기(ELEC)** / **공조(AIR)**: 개별 토글

### 4.2 Zone 표시

**"Zone 표시"** 버튼으로 HVAC Zone 노드 표시/숨김 가능.
Zone은 최우측 열에 배치되며, 해당 Zone에 공급하는 장비와 점선으로 연결됩니다.

### 4.3 검색

검색창에 장비 이름 입력 시 해당 장비로 카메라가 자동 이동합니다.

### 4.4 통계

하단에 현재 표시 중인 레벨 수, 노드 수, 엣지 수, Zone 수가 표시됩니다.

## 5. 기술 아키텍처

### 5.1 데이터 흐름

```
Neo4j (feeds 관계 260개)
  ↓ GET /api/topology/connections
Frontend: buildGlobalDAG() → BFS 레벨 할당 → ReactFlow 렌더링
  ↓ SSE (실시간 센서 데이터)
장비 카드 가동률/상태 업데이트 (0.5초 주기)
```

### 5.2 장애 파급 분석 API

```
GET /api/topology/fault-impact?equipment=Chiller_1&max_depth=5

Neo4j Cypher: MATCH path = (source)-[:feeds*1..5]->(affected)
→ depth별 impact_level 분류 → JSON 응답
```

### 5.3 관련 소스 코드

| 파일 | 역할 |
|------|------|
| `equip-topology-layout.ts` | Global DAG 빌드 + BFS 레벨 할당 + 노드/엣지 배치 |
| `equip-topology-data.ts` | API 호출 + 데이터 조합 |
| `equip-topology-nodes.tsx` | 커스텀 노드 컴포넌트 (FlowEquipCard, LevelLabel, ZoneNode) |
| `equip-topology-canvas.tsx` | ReactFlow 캔버스 + Impact 모드 + SSE 연동 |
| `equip-topology-controls.tsx` | 필터/검색/토글 컨트롤 패널 |
| `neo4j_service.py` | `get_fault_impact()` — Neo4j feeds 경로 추적 |
| `ontology.py` | `GET /api/topology/fault-impact` 엔드포인트 |

## 6. 개선 가능 사항

1. **Isolated 장비 축소**: `feeds` 관계가 없는 장비(L999)가 많으면, 온톨로지에서 feeds 관계를 보강하여 DAG에 편입
2. **중간 단계 보강**: Chiller가 CC_Panel에 직접 feeds하는 경우, Pump → Header 중간 경로 추가 가능
3. **역방향 분석**: 현재는 "이 장비가 고장나면?" (하류 추적)만 지원. "이 Zone이 영향받으려면?" (상류 추적) 추가 가능
