# BEES 디지털 트윈 플랫폼 설계안 v2

> 최종 수정: 2026-02-11
> 상태: 검토 중 (사용자 승인 대기)
> ⚠️ **주의:** 이 문서는 초기 설계 초안입니다. Grafana·WebSocket·i18n 등 이후 실제 구현과 다를 수 있으며, 현재 구현 상태의 정본은 `_docs/11_프로젝트_결과물_요약.md` 입니다.

## Context

삼성물산 GEC B동의 Brick Schema 온톨로지(1,597 인스턴스, 11,527 트리플)를 기반으로 **4개 독립 서버**로 구성된 디지털 트윈 IoT 시뮬레이션 플랫폼을 구축한다. 가상 건물 에뮬레이터가 실시간 센서 데이터를 생성하고, 웹 대시보드에서 장비 모니터링/제어, 알람 관리, 에너지 분석, 온톨로지 기반 지식 조회가 가능한 시스템.

**기술 선택**:
- 프로토콜: Phase 1 REST + MQTT → Phase 2 BACnet 어댑터 추가
- LLM: OpenAI GPT (Function Calling → Neo4j Cypher)
- 프론트엔드: Next.js (React) + TypeScript
- 시계열 DB: **InfluxDB** (IoT 특화, 고속 쓰기, Python 클라이언트 우수)
- RDBMS: **PostgreSQL** (관리자/유지보수/감사 데이터, JSON 지원, 복잡 쿼리 우수)
- 그래프 DB: Neo4j (기존, 온톨로지)

## 2. 데이터베이스 전략

### InfluxDB (시계열 데이터)
- **용도**: 센서 실시간 데이터, 에너지 데이터, 장비 운전 데이터
- **선택 이유**: IoT 특화 고속 쓰기, 자동 다운샘플링 Task, Flux 쿼리, Docker 간단 설정
- **워크로드**: 845 포인트 × 5초 간격 = ~169 포인트/초 (InfluxDB에 매우 가벼운 부하)
- **보존 정책**:
  - `raw_7d`: 5초 해상도 원시 데이터, 7일 보존
  - `downsampled_90d`: 1분 집계, 90일 보존
  - `archive_2y`: 1시간 집계, 2년 보존
  - `permanent`: 1일 집계, 영구 보존

### PostgreSQL (관계형 데이터)
- **용도**: 관리자/사용자 정보, 장비 메타데이터, 유지보수 기록, 알람 이력, 감사 로그
- **선택 이유**: JSON 지원, pgAudit 감사 로깅, 복잡 JOIN 성능 우수, 넓은 생태계
- **주요 테이블**:


### Neo4j (그래프 DB — 기존)
- **용도**: Brick Schema 온톨로지 (구조, 관계, 시맨틱 조회)
- **현황**: 11,527 트리플, 1,597 인스턴스 로드 완료
- **역할**: 장비-공간-시스템 관계 탐색, LLM Cypher 쿼리, 토폴로지 시각화

## 3. Server A: 온톨로지 웹 서비스 (상세)

### 3.1 대시보드 (메인 페이지 `/`)

**건물 전체 현황 (Single Pane of Glass)**
- KPI 카드 4개: 현재 전력(kW), 활성 장비 수, 활성 알람 수(심각도별), 평균 실내 온도
- 시스템 상태 요약: HVAC/조명/전기/보안 — 각각 초록(정상)/노랑(주의)/빨강(이상)
- 24시간 에너지 소비 프로파일 차트
- 최근 알람 목록 (최신 5건, 심각도 색상 표시)
- 층별 쾌적도 히트맵 (온도 기준 색상 매핑)

### 3.2 장비 모니터링 (`/monitoring`)

**장비 목록 뷰**
- 테이블: 장비명 | 위치 | 상태(ON/OFF/대기/오류) | 주요 센서값 | 마지막 업데이트
- 필터: 장비 유형별, 층별, 시스템별, 상태별
- 검색: 장비명/ID 검색

**장비 상세 페이지 (`/monitoring/{equipmentId}`)**

클릭 시 해당 장비의 전용 모니터링 페이지:

| 영역 | 내용 |
|------|------|
| **상태 헤더** | 장비명, Brick 클래스, 위치, 운전 상태 배지, 가동 시간 |
| **실시간 게이지** | 주요 센서값 게이지 (온도, 압력, 유량 등) — 정상/주의/위험 색상 구간 |
| **실시간 트렌드 차트** | 5초 간격 라이브 업데이트 라인 차트. 줌/팬 가능. 시간 범위 선택 (1시간/24시간/7일/30일/커스텀) |
| **다중 센서 오버레이** | 여러 센서를 하나의 차트에 겹쳐 표시 (토글 On/Off) |
| **설정값 비교** | 실측값 vs 설정값(setpoint) 대비 표시. 편차 시 노랑/빨강 하이라이트 |
| **연결 장비** | 상위 시스템, 하위 장비, 공급(feeds) 관계, 위치(zone/floor) |
| **알람 이력** | 이 장비의 최근 알람 목록 (최근 30일) |
| **유지보수 이력** | 이 장비의 작업 주문 이력, 다음 정비 예정일 |
| **성능 지표** | 일/주/월 평균, 최대, 최소, 가동률(%) |

**장비 유형별 센서 구성**:
- **AHU**: 급기온도, 환기온도, 혼합공기온도, 필터차압, 댐퍼 위치, VFD 주파수
- **Chiller**: 급수온도, 환수온도, 압축기 전류, 냉매 압력, COP
- **Boiler**: 급수온도, 환수온도, 가스 사용량, 효율
- **조명**: 조도(lux), ON/OFF 상태, 디밍 레벨(%)

### 3.3 제어 관리 (`/control`)

**제어 대시보드**
- 장비 목록 + ON/OFF 토글 스위치 + 운전 상태 표시등
- 제어 가능 장비만 필터 (Command/Setpoint 포인트가 있는 장비)
- 역할 기반 제어 제한: viewer=읽기 전용, operator=설정값 조정, admin=전체

**개별 장비 제어 패널**:

| 제어 기능 | 상세 |
|-----------|------|
| **ON/OFF 제어** | 토글 스위치 + 확인 다이얼로그. 위험 장비는 잠금(Lock) 기능 |
| **설정값(Setpoint) 조정** | 슬라이더 또는 ±0.5 증감 버튼. 현재값/설정값/편차 동시 표시. 안전 범위 표시 |
| **운전 모드 선택** | 드롭다운: 자동/수동/대기/비점유/점유/비상/정지 |
| **스케줄 관리** | 주간 스케줄 타임블록 에디터. 드래그로 시간 조정. 공휴일/특별일 예외 설정 |
| **오버라이드(임시 변경)** | 기간 선택(1시간/4시간/24시간), 자동 복귀, 노랑 배지로 오버라이드 활성 표시 |
| **그룹 제어** | 다중 장비 선택 → 일괄 명령. 층별/시스템별 그룹 프리셋 저장 |
| **인터락 시각화** | 장비 간 의존 관계 다이어그램. 어떤 장비가 어떤 장비를 차단하는지 표시 |
| **명령 피드백** | 전송 중 스피너 → 성공 토스트(초록) 또는 실패+재시도(빨강). 읽기 확인(readback) |
| **명령 이력** | 최근 명령 10건: 시각, 사용자, 대상, 이전값→새값, 결과 |

### 3.4 알람 관리 (`/alarms`)

**활성 알람 대시보드**
- 심각도별 카운트 배지: Critical(빨강) / Major(주황) / Minor(노랑) / Info(파랑)
- 테이블: 심각도 | 시각 | 장비 | 알람유형 | 현재값 vs 임계값 | 상태 | 조치 버튼
- 필터: 심각도별, 장비별, 층별, 시간대별, 미확인만
- [확인(Ack)] → 담당자/예상 해결시간 입력 모달
- [억제(Suppress)] → 기간 선택(1시간/1일), 사유 입력
- 알람 집약: 1개 근본 원인으로 5개 연쇄 알람 발생 시 그룹화

**알람 상세 패널**
- 알람 설명 및 권장 조치
- 해당 센서의 트렌드 차트 (알람 시점 전후)
- 연결 장비 (상위/하위)
- 과거 동일 알람 발생 이력
- 관련 유지보수 기록

**알람 이력 (`/alarms/history`)**
- 검색/필터 가능한 아카이브
- 각 알람: 발생시각, 해제시각, 지속시간, 확인자, 해결 조치

**알림 채널 설정**
- 이메일 (즉시 + 일일 다이제스트)
- SMS (Critical만)
- 브라우저 푸시 알림
- 에스컬레이션: 15분 미확인→SMS, 30분→전화

### 3.5 에너지 분석 (`/energy`)

| 섹션 | 내용 |
|------|------|
| **실시간 전력** | 현재 건물 부하(kW) 대형 숫자 + 24시간 프로파일 + 피크 표시 |
| **시스템별 분석** | HVAC/조명/전기/기타 비율 파이 차트 + 각각의 추이 |

| **층별 비교** | 바 차트: 층별 에너지 사용량 비교 |
| **EUI 지표** | kWh/m²/년 — 벤치마크 대비 표시 |

### 4.2 명령 큐잉 & 재시도
- 오프라인 장비에 대한 명령 큐 (FIFO)
- 재시도 전략: 지수 백오프 (1초→2초→4초→8초→16초), 최대 5회
- 최대 명령 수명: 30분 (초과 시 만료 처리)
- 위험 명령(안전 정지) 우선 큐잉
- 2단계 확인: 명령 전송 → 2초 대기 → readback 확인

### 4.3 프로토콜 변환
- Phase 1: REST → REST (Server C)
- Phase 2: REST → BACnet/IP WriteProperty (BAC0 라이브러리)
- 내부 공통 스키마:
  ```json
  {
    "equipment_id": "AHU_5F",
    "point_type": "SupplyAirTemperature",
    "value": 13.2,
    "unit": "celsius",
    "timestamp": "2026-02-11T14:32:45Z",
    "source_protocol": "REST"
  }
  ```

### 4.4 감사 로깅
- 모든 명령 기록: 시각, 사용자, 대상, 이전값→새값, 결과, 재시도 횟수
- PostgreSQL `audit_log` 테이블 저장
- 프로토콜 수준 이벤트 로그 (BACnet Who-Is, 타임아웃 등)

### 4.5 헬스 모니터링
- 장비별 상태: 초록(정상)/노랑(느림)/빨강(오프라인)/회색(미등록)
- 통신 품질: 응답시간, 패킷 손실률, 업타임(%)
- 게이트웨이 리소스: CPU, 메모리, 디스크

**주요 의존성**: `fastapi`, `uvicorn`, `paho-mqtt`, `httpx`, `asyncpg`

### 5.2 HVAC 열역학 모델링

1차 에너지 밸런스 방정식:
```
dT_zone/dt = (U·A·(T_out - T_zone) + Q_solar·A_window + Q_internal - Q_HVAC) / (ρ·Cp·V)
```
- U·A: 열손실 계수 (W/K)
- Q_solar: 태양열 획득 (방위+시간 기반)
- Q_internal: 재실+장비 내부 발열
- Q_HVAC: 냉난방 출력
- 열시정수 τ = 30~60분 (존별)

PI 제어 루프 시뮬레이션:
- 설정값 추적 응답시간 ~15분
- 오버슈트 ~1~2°C
- 급기온도 변화 → 존 온도 반영 시 지연(열 관성)

### 6.2 InfluxDB 다운샘플링

```flux
// 5분 다운샘플링 Task (매 5분 실행)
option task = {name: "downsample_5m", every: 5m}
from(bucket: "raw_7d")
  |> range(start: -10m)
  |> aggregateWindow(every: 5m, fn: mean)
  |> to(bucket: "downsampled_90d")

// 1시간 다운샘플링 Task (매 1시간 실행)
option task = {name: "downsample_1h", every: 1h}
from(bucket: "downsampled_90d")
  |> range(start: -2h)
  |> aggregateWindow(every: 1h, fn: mean)
  |> to(bucket: "archive_2y")
```

### 6.3 데이터 품질 관리
- **범위 검증**: 온도 -10~50°C, 습도 0~100% 범위 밖 = bad 태깅
- **변화율 검증**: 분당 온도 변화 >10°C = 센서 이상 의심
- **이상치 탐지**: 이동 평균 ±3σ 초과 = 이상치 플래그
- **누락 데이터**: 5분 이상 데이터 없으면 gap 표시, 대시보드에 점선 처리
- **품질 메타데이터**: 각 포인트에 status 태그 (good/uncertain/bad/substituted)

### 6.4 데이터 내보내기
- 형식: CSV, Excel(.xlsx), JSON, Parquet
- 시간 범위 + 장비 + 지표 + 집계 수준 선택
- 대용량(>100MB): 백그라운드 작업 → 완료 시 이메일 링크
- 정기 내보내기 스케줄링 (매주/매월 자동)

**주요 의존성**: `fastapi`, `uvicorn`, `influxdb-client`, `asyncpg`, `paho-mqtt`

## 8. 데이터 영속성 원칙

### 핵심 원칙
> **컨테이너 내부에는 어떤 영구 데이터도 저장하지 않는다.**
> 모든 데이터는 호스트 PC의 `./data/` 하위 **컨테이너별 독립 폴더**에 저장한다.
> 컨테이너는 순수하게 프로그램 실행만 담당한다.

### 장점
- **데이터 안전**: 컨테이너 삭제/업그레이드해도 데이터 유지
- **백업 용이**: `data/` 폴더만 복사하면 전체 백업 완료
- **용량 관리**: 호스트 디스크 모니터링으로 충분
- **이식성**: `data/` 폴더를 다른 PC로 옮기면 그대로 복원 가능

### 호스트 볼륨 마운트 구조

```
data/                              ★ 모든 영구 데이터 (호스트 저장, .gitignore 등록)
├── neo4j/                         # Neo4j 전용 — 그래프 DB 데이터
│   ├── data/
│   └── plugins/
├── influxdb/                      # InfluxDB 전용 — 시계열 데이터
├── postgres/                      # PostgreSQL 전용 — RDBMS 데이터
├── mosquitto/                     # Mosquitto 전용 — 메시지 로그
│   ├── data/
│   └── log/
├── server-a/                      # Server A 전용
│   └── logs/                      #   애플리케이션 로그
├── server-b/                      # Server B 전용
│   ├── db/                        #   SQLite (명령 이력)
│   └── logs/                      #   애플리케이션 로그
├── server-c/                      # Server C 전용
│   ├── snapshots/                 #   시뮬레이션 상태 스냅샷
│   └── logs/                      #   애플리케이션 로그
└── server-d/                      # Server D 전용
    ├── export/                    #   CSV/Excel 내보내기 파일
    └── logs/                      #   애플리케이션 로그
```

> **주의**: `data/` 폴더는 `.gitignore`에 등록하여 Git에 포함되지 않도록 한다.
> 각 컨테이너는 자기 전용 폴더만 사용하며, 절대 다른 컨테이너의 폴더에 접근하지 않는다.

## 11. 검증 계획

### 단계별 검증
1. `docker compose up -d` → 모든 서비스 healthy
2. `mosquitto_sub -t "bees/#"` → MQTT 데이터 수신 확인
3. Server C `/simulation/start` → MQTT 센서 데이터 발행
4. InfluxDB UI (localhost:8088) → 데이터 적재 확인
5. `POST /api/control` → Server B → C 장비 상태 변경 → 데이터 생성 시작/중지
6. 브라우저 localhost:3000 → 실시간 차트 업데이트 확인
7. 장비 클릭 → 상세 모니터링 페이지 → 실시간 그래프 확인
8. LLM 채팅 → "5층 AHU 센서는?" → Cypher 응답

### 통합 시나리오 테스트
```bash
# 1. AHU_5F 켜기
curl -X POST http://localhost:8010/api/control \
  -H "Content-Type: application/json" \
  -d '{"deviceId": "bldg:AHU_5F", "command": "ON"}'

# 2. 5초 후 데이터 확인
curl http://localhost:8013/data/points/bldg:Zone_Air_Temp_5F_Interior/latest

# 3. 알람 확인
curl http://localhost:8013/alarm-history?equipment=bldg:AHU_5F

# 4. 감사 로그 확인
curl http://localhost:8013/audit-log?limit=5
```
