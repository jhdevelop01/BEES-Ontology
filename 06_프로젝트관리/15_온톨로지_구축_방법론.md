## 1. 전체 프로세스 개요

### 1.1 구축 단계 흐름

```
┌─────────────────────────────────────────────────────────────────┐
│  Step 1. 건물 기본정보 (공개 데이터)                              │
│  ├── 건축물대장 (세움터/정부24)                                   │
│  ├── 부동산 포털 (OfficFind, Naver부동산)                         │
│  └── 설계사 포트폴리오 (HOK, SAMOO 등)                           │
│                          ▼                                       │
│  Step 2. 인증 정보                                                │
│  ├── LEED (USGBC 프로젝트 검색)                                  │
│  ├── G-SEED (gseed.or.kr, AURUM)                                │
│  └── 에너지효율등급 (beec.energy.or.kr)                           │
│                          ▼                                       │
│  Step 3. ESG/에너지 데이터                                        │
│  ├── ESG보고서 PDF 직접 추출                                     │
│  ├── 서울시 에너지다소비건물 공개자료                               │
│  ├── 공공데이터포털 건물에너지 API                                 │
│  └── DitchCarbon / CDP                                           │
│                          ▼                                       │
│  Step 4. 기술정보 (학술논문/특허)                                  │
│  ├── KCI / RISS / DBpia / Google Scholar                         │
│  ├── KIPRIS (특허)                                                │
│  └── MDPI / ASCE / ASHRAE (국제논문)                             │
│                          ▼                                       │
│  Step 5. 법규 역추론 (건축법, 소방법, 전기사업법)                   │
│  Step 6. 유사건물 벤치마킹 (용도/규모/준공년도 유사)                │
│  Step 7. 공학적 계산 (부하계산, ASHRAE 기준, 물수지 등)            │
│                          ▼                                       │
│  Step 8. 온톨로지 TTL 작성 (Brick Schema 1.3+)                   │
│  Step 9. 검증 (rdflib 파싱 + pyshacl SHACL 검증)                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 데이터 신뢰도 3단계

모든 데이터 항목에 반드시 신뢰도를 태깅한다.

| 등급 | TTL 값 | 의미 | 전형적 출처 |
|------|--------|------|-------------|
| **confirmed** | `"confirmed"` | 공식 문서/인증서에서 직접 확인 | 건축물대장, LEED 인증서, ESG보고서 |
| **estimated** | `"estimated"` | 공학적 계산/벤치마킹으로 추정 | 부하 계산, 유사건물 비교, 면적비례 |
| **inferred** | `"inferred"` | 법규/규정에서 역추론 | 소방시설법, 전기사업법, 건축법 |

### 1.3 GEC B동 적용 결과 요약

| 단계 | 확보 항목수 | 누적 확보율 | 온톨로지 변화 |
|------|:----------:|:----------:|---------------|
| Step 1~3 (공개데이터) | 75건 confirmed | ~56% | v1.0 (~500 트리플) |
| Step 4~6 (논문/법규/벤치마킹) | +45건 estimated/inferred | ~90% | v1.3 (~1,100 트리플) |
| Step 7 (공학적 추정) | +14건 estimated | 100% | v1.7 (2,024 트리플) |

## 2. Step 1: 건물 기본정보 수집

### 2.1 건축물대장 (필수, 최우선)

**출처:** 세움터 (eais.go.kr) 또는 정부24 (gov.kr)

**수집 방법:**
1. 세움터 → 건축물대장 → 주소 검색 (도로명 또는 지번)
2. 표제부(총괄) + 표제부(동별) 열람
3. 필요 시 일반건축물대장 발급

**수집 항목:**
| # | 항목 | 온톨로지 매핑 | GEC B동 실제 값 |
|---|------|---------------|-----------------|
| 1 | 대지면적 | `bees:siteArea` | 27,604 m² |
| 2 | 연면적 | `bees:grossFloorArea` | 186,023 m² (전체) |
| 3 | 건축면적 | `bees:buildingArea` | 14,506 m² |
| 4 | 건폐율/용적률 | `bees:buildingCoverageRatio`, `bees:floorAreaRatio` | 52.55% / 364.38% |
| 5 | 층수 | `brick:Floor` 인스턴스 수 | B4F~15F (18개 층) |
| 6 | 구조 | `bees:structureType` | 철근콘크리트(RC) |

| 8 | 준공일 | `bees:completionYear` | 2012 |

**주의사항:**

- 연면적은 B동 단독이 아닌 전체인 경우가 많음 → 동별 면적은 별도 추정 필요

## 3. Step 2: 인증 정보 확보

### 3.1 LEED 인증

**출처:** USGBC 프로젝트 검색 (usgbc.org/projects)

**검색 방법:**
1. USGBC 웹사이트 → Projects 검색
2. 건물명/도시명으로 검색
3. 프로젝트 페이지에서 인증 등급, 점수, 인증일, 인증 시스템 확인

**GEC 사례:**
| # | 확보 데이터 | 값 | 비고 |
|---|-------------|-----|------|
| 1 | 인증 등급 | Gold | USGBC 직접 확인 |
| 2 | 인증 시스템 | NC v2.2 | 이전 v2009 추정 → v2.2로 수정 |
| 3 | 총점 | 45점/69점 | hasScorecard: true |
| 4 | 인증일 | 2012.05.23 | USGBC 직접 확인 |
| 5 | 크레딧별 상세 | 6개 카테고리 추정 | JS 렌더링 필요 → 역추정 |

**크레딧별 역추정 방법 (스코어카드 미공개 시):**
1. 건물의 알려진 친환경 특성을 LEED 크레딧 요구사항과 교차 대조
2. 각 크레딧의 필수(Prerequisite) 항목은 반드시 충족으로 판단
3. 카테고리별 합산이 총점(45점)과 일치하도록 조정
4. 결과: SS 9 / WE 4 / EA 12 / MR 5 / IEQ 11 / ID 4 = 45점

### 3.2 G-SEED (녹색건축인증)

**출처:**
- 녹색건축인증 시스템 (gseed.or.kr) — 공식 DB
- AURUM 건축정보 (aurum.re.kr) — 건축물 인증 정보 수집

## 4. Step 3: ESG/에너지 데이터 수집

### 4.1 ESG 보고서 PDF 직접 분석

**출처:** 건물 소유/운영사 ESG/지속가능경영 보고서

**수집 방법:**
1. 기업 공식 웹사이트 → 지속가능경영 → 보고서 다운로드
2. PDF에서 "본사", "사옥", "GEC" 등 키워드로 건물 단위 데이터 검색
3. **핵심:** 전사 데이터와 건물(본사) 데이터를 반드시 구분

**GEC 사례 — 삼성E&A ESG 보고서에서 확보:**
| # | 데이터 | 값 | 연도 | 출처 |
|---|--------|-----|------|------|
| 1 | GEC 본사 GHG | 12,872 tCO2e | 2024 | ESG PDF 직접 추출 |
| 2 | GEC 본사 GHG | 10,943 tCO2e | 2023 | ESG PDF 직접 추출 |
| 3 | GEC 본사 GHG | 11,123 tCO2e | 2022 | ESG PDF 직접 추출 |
| 4 | 넷제로 목표 | 2050년 | — | ESG 보고서 |
| 5 | RE100 목표 | 2030년 | — | ESG 보고서 |
| 6 | Scope1+2 감축 | 45% (2018 대비) | — | ESG 보고서 |

### 4.2 서울시 에너지다소비건물 공개자료

**출처:** 서울시 에너지정보 포털 또는 서울 열린데이터광장

**수집 데이터:** 에너지 소비량(TOE), GHG 배출량(tCO2eq), 면적당 GHG 원단위

**GEC 사례:**
| 항목 | 값 | 비고 |
|------|-----|------|
| GEC 전체 에너지 | 6,143 TOE | 2019년 기준, confirmed |
| GEC 전체 GHG | 11,671 tCO2eq | confirmed |
| GHG 원단위 | 0.128 tCO2/m² | confirmed |
| 순위 | 94위/324개소 | 서울시 에너지다소비 사업장 |

**B동 분리 추정:**
- B동 면적비율 = 61,700 / 191,000 ≈ 32.3%
- B동 에너지 ≈ 6,143 × 0.323 ≈ 1,984 TOE
- B동 GHG ≈ 11,671 × 0.323 ≈ 3,770 tCO2eq
- EUI = 6,143 TOE × 11,630 kWh/TOE / 186,023 m² ≈ 384 kWh/m²/년

## 8. Step 7: 공학적 계산 기반 추정

### 8.1 냉방부하 → 칠러 용량 계산

```
입력:
  B동 연면적 = 61,700 m²
  냉방면적 비율 = 65% (기계실/주차장 제외)
  유효 냉방면적 = 61,700 × 0.65 = 40,105 m²
  부하밀도 = 150 W/m² (서울 오피스 표준)

계산:
  총 냉방부하 = 40,105 × 150 = 6,016 kW
  RT 환산 = 6,016 / 3.517 = 1,710 RT
  안전율 1.1 적용 = 1,710 × 1.1 ≈ 1,880 RT

결과:
  → 4대 × 500 RT (고부하) 또는 4대 × 1,500 RT (여유 포함)
  → GEC: 4대 × 1,500 RT 채택 (3+1 백업, 유사건물 기준)
  → Trane CVHE 또는 Carrier 19XR 추론 (2012년 한국 대형 칠러 주요 제조사)
```

### 8.2 환기량 → AHU/DOAS 풍량 계산

```
입력:
  기준층 면적 = 3,500~4,400 m² (B동 추정)
  재실밀도 = 10 m²/인 (ASHRAE 62.1, 오피스)
  층당 재실인원 = 4,000 / 10 = 400명
  1인당 외기량 = 10 L/s (ASHRAE 62.1)
  면적당 외기량 = 0.6 L/s·m² (ASHRAE 62.1)

계산:
  층당 외기량 = (400 × 10) + (4,000 × 0.6) = 6,400 L/s = 23,040 CMH
  UFAD 순환풍량 = 외기량 × 2.0 배 (가압플레넘) = 46,080 CMH
  반올림 → 47,000 CMH/층

결과:
  AHU: 11대 × 47,000 CMH (오피스층 6F~15F, 11개 층, 층당 1대)
  DOAS: 3대 × 24,000 CMH (B1/1F/2F 공용부, 외기 전담)
```

### 8.3 전기부하 → 수전용량 계산

```
입력:
  B동 연면적 = 61,700 m²
  부하밀도 = 80 W/m² (서울 대형 오피스 표준, 일반부하+동력)
  역률 = 0.85

계산:
  총 부하 = 61,700 × 80 = 4,936 kW
  피상전력 = 4,936 / 0.85 = 5,807 kVA
  반올림 → 6,000 kVA

결과:
  수전 계약: 6,000 kVA (특고압 22.9 kV)
  변압기: 6대 (1,000 kVA급, 3상)
  비상발전: 1,200 kVA (수전의 20%, 소방+방재+IT)
  MDP: 1대 (Switchgear), 층별 분전반 18개
```

### 8.4 물수지 → 중수처리 용량 계산

```
입력:
  B동 재실인원 = 2,000명
  1인 용수 사용량 = 100 L/일 (업무시설 표준)
  하수 발생률 = 80%
  중수 재이용률 = 40%

계산:
  총 용수 = 2,000 × 100 = 200 m³/일
  하수 발생 = 200 × 0.80 = 160 m³/일
  중수 처리 = 160 × 0.40 = 64 m³/일

결과:
  중수처리 용량: 64 m³/일
  처리수 저장탱크: 100 m³ (1.5일분)
  빗물저류 탱크: 50 m³ (조경관수용)
```

### 8.5 승강기 대수 → 5분 수송능력 계산

```
입력:
  B동 수용인원 = 2,000명
  피크 15분 도착률 = 12% (오피스 표준)
  5분 수송능력 목표 = 12% / 3 = 4%
  5분 수송 인원 = 2,000 × 0.04 = 80명

  승강기 사양 (가정):
    정원 = 17인 (1,150 kg)
    속도 = 2.5 m/s
    최상층 이동시간 = 60m / 2.5 = 24초
    1회 왕복시간 (RTT) = 약 90초 (정차/승하차 포함)
    5분간 왕복 횟수 = 300 / 90 ≈ 3.3회
    1대 5분 수송 = 17 × 3.3 × 0.8(적재율) ≈ 45명...

  수정: 중간층 정차 고려 RTT = 120초
    1대 5분 수송 = 17 × 2.5 × 0.8 ≈ 34명... → 역시 높음
    실제 적재율 60%: 17 × 2.5 × 0.6 ≈ 25명

계산:
  필요 대수 = 80 / (17 × 2.5 × 0.6) = 80 / 25.5 ≈ 3.1대 (최소)
  실용 대수 = 8대 (양방향 운행, 대기시간 30초 이내 서비스 기준)

  GEC 전체 37대 중 B동 배분:
  37 × (2,000/7,000) ≈ 10.6대 → 10대 (승용8+화물1+비상1)

결과:
  승용: 8대 (1,150 kg/17인, 2.5 m/s)
  화물: 1대 (2,000 kg, 1.0 m/s)
  비상: 1대 (1,150 kg, 소방용)
```

### 9.2 인스턴스 작성 패턴

**기본 패턴 (모든 인스턴스):**
```turtle
bldg:Instance_Name a brick:Class_Name ;
    rdfs:label "사람이 읽을 수 있는 이름" ;
    brick:isPartOf bldg:Parent_Instance ;
    bees:hasConfidence "confirmed" ;  # 또는 "estimated" / "inferred"
    rdfs:comment "설명 텍스트" .
```

**추정 데이터 패턴:**
```turtle
bldg:Estimated_Instance a brick:Class_Name ;
    rdfs:label "추정 인스턴스 이름" ;
    brick:isPartOf bldg:Parent ;
    bees:hasConfidence "estimated" ;
    bees:estimatedRange "범위 표현 (예: 300~500 sensors)" ;
    bees:inferenceSource "출처 (논문/벤치마킹/법규/계산)" ;
    rdfs:comment "추정 근거 설명" .
```

**법규 역추론 데이터 패턴:**
```turtle
bldg:Inferred_Instance a brick:Class_Name ;
    rdfs:label "역추론 인스턴스 이름" ;
    brick:isPartOf bldg:Parent ;
    bees:hasConfidence "inferred" ;
    bees:inferenceSource "소방시설법 시행령 별표5" ;
    rdfs:comment "법규 근거 설명" .
```

### 9.3 관계(Relationship) 모델링

```turtle
# 위계 관계
bldg:Floor → brick:isPartOf → bldg:Building
bldg:Zone  → brick:isPartOf → bldg:Floor
bldg:Equipment → brick:isPartOf → bldg:System

# 에너지/유체 흐름
bldg:Chiller_Plant → brick:feeds → bldg:UFAD_System
bldg:AHU_1 → brick:feeds → bldg:B_6F_Interior_Zone
bldg:Boiler → brick:feeds → bldg:Radiant_Heating_System

# 센서 연결
bldg:Sensor → brick:isPointOf → bldg:Equipment
bldg:Sensor → brick:hasLocation → bldg:Zone
```

| 10 | EUI | `에너지(TOE) × 11,630 / 연면적` | 에너지소비량 | 384 kWh/m² |
| 11 | 월별배분 | `기저(42%균등) + 냉방(CDD비례) + 난방(HDD비례)` | 연간에너지 | 12개월 |
| 12 | BMS 포인트 | `Σ(장비수 × 장비당포인트수)` | 장비 목록 | ~1,600 |
| 13 | DDC 수 | `Zone DDC + AHU DDC + Plant DDC + Misc` | 층수/장비수 | 80~100대 |
| 14 | 공간배분 | `기준층 × {오피스0.80, 회의0.12, 서버0.03, 지원0.05}` | 기준층면적 | 면적비율 |
